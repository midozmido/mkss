# ناشر المقالات الآلي — WordPress REST API

أداة تنشر المقالات على أي موقع ووردبريس من ملفات Markdown، عبر REST API و Application Password.
مش محتاجة أي بلجن على الموقع.

## هل ينفع بالبيانات دي؟

`Application Password` + `/wp-json/wp/v2` هي الطريقة الرسمية المدعومة من ووردبريس للنشر الآلي.

| العملية | مدعومة |
|---|---|
| إنشاء وتحديث المقالات | ✓ |
| جدولة النشر لتاريخ مستقبلي | ✓ |
| رفع الصور وتحديد الصورة البارزة | ✓ |
| إنشاء التصنيفات والوسوم لو مش موجودة | ✓ |
| حفظ كـ draft للمراجعة قبل النشر | ✓ |
| الـ SEO meta (Yoast / RankMath / AIOSEO) | حسب إعداد البلجن — شوف الأسفل |

## التشغيل

```bash
cd wp-publisher
pip install -r requirements.txt

cp .env.example .env      # وحُط بياناتك جواه
python3 wp_publish.py doctor
```

`doctor` بيختبر 4 حاجات ويقولك بالظبط إيه الشغال: وصول REST API، المصادقة،
الصلاحيات (نشر / تعديل / رفع صور / تصنيفات)، وقراءة المقالات. **بيرجّع exit code ≠ 0
لو أي حاجة مطلوبة ناقصة** — فينفع تعتمد عليه في CI.

بعد كده:

```bash
python3 wp_publish.py publish --all --dry-run   # معاينة — صفر كتابة على الموقع
python3 wp_publish.py publish --all             # المقال الجديد بينزل draft
python3 wp_publish.py publish --all --status publish   # نشر مباشر
```

## شكل ملف المقال

ملف `.md` في `content/`. `title` هو الحقل الوحيد الإلزامي. ابدأ من `content/_template.md`.

```markdown
---
title: عنوان المقال
slug: article-slug
status: draft
categories: [Insights]
tags: [import, logistics]
featured_image: ../images/hero.jpg
date: 2026-10-01T09:00:00
---

نص المقال بالـ Markdown.
```

| الحقل | السلوك |
|---|---|
| `title` | **إلزامي.** لو مش موجود، بيتاخد من أول `# عنوان` في النص (والعنوان بيتشال من النص) |
| `slug` | لو فاضي بيتولّد من العنوان. لو العنوان مفيهوش حروف صالحة، الأداة بتفشل بدل ما تخمّن |
| `status` | `draft` \| `publish` \| `pending` \| `private`. الافتراضي للمقال الجديد: `draft` |
| `categories` / `tags` | قائمة `[أ, ب]` أو نص مفصول بفواصل. بتتعمل لو مش موجودة |
| `excerpt` | لو فاضي بيتولّد من أول فقرة كاملة |
| `seo_title` / `seo_description` | بيتبعتوا لـ Yoast و RankMath و AIOSEO، والأداة بتتحقق أي واحد استلم |
| `featured_image` | مسار نسبي جوه المشروع، أو URL على https |
| `featured_alt` | النص البديل للصورة |
| `date` | `2026-10-01` أو `2026-10-01T09:00:00`. مع `status: publish` وتاريخ مستقبلي → نشر مجدول |
| `author` | رقم (id اليوزر) |
| `comment_status` | `open` \| `closed` |
| `dir` | `rtl` = محاذاة يمين. الافتراضي: اتجاه الموقع |

المفاتيح الفاضية (زي `slug:` بدون قيمة) بتتجاهل وتاخد الافتراضي. أي قيمة فيها `:` حُطها
بين علامتي تنصيص.

**التحويل:** الـ Markdown بيتحول لـ **Gutenberg Blocks** — مش HTML صمّاء — فالمقال يفتح في
محرر ووردبريس وتعدّله بالبلوكات عادي. المدعوم: عناوين (الـ `#` بيترقّى لـ h2 لأن ووردبريس
بياخد الـ h1 لعنوان المقال)، فقرات، قوائم متداخلة، اقتباسات، جداول، كود بلغة، صور بتعليق،
فواصل، HTML خام (منقّى)، وتنسيقات السطر.

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `doctor` | اختبار الاتصال والمصادقة والصلاحيات. exit ≠ 0 لو فيه مشكلة |
| `list [--limit N]` | آخر المقالات على الموقع بحالتها وروابطها |
| `publish --all` | نشر/تحديث كل `content/*.md` (الملفات اللي بتبدأ بـ `_` بتتجاهل) |
| `publish FILE...` | ملفات محددة بالاسم |
| `--dry-run` | معاينة بدون أي كتابة، وبتقول هيعمل مقال جديد ولا هيحدّث موجود |
| `--status` | يتخطى الحالة المكتوبة في الملف — **وبيتطبّق على المقالات الموجودة كمان** |
| `-v` | تفاصيل أكتر (الصور، السيو) |

## سلوك مهم تعرفه

### التشغيل مرتين مش بيعمل تكرار

الأداة بتلاقي المقال الموجود بالترتيب ده:

1. **رقم المقال المسجّل** في `.published.json` لكل ملف — ده الأساس، فلو ووردبريس غيّر الـ slug
   (بيحصل لما يكون فيه مقال بنفس الـ slug) الأداة بتفضل تحدّث نفس المقال وبتنبّهك.
2. **الـ slug** لو مفيش سجل.

يعني آمن تشغّل `publish --all` كل يوم في cron أو CI.

### الحالة مش بترجع لورا

- **مقال جديد**: بياخد الحالة من الملف، والافتراضي `draft`.
- **مقال موجود**: الأداة **مش بتغيّر حالته** إلا لو الملف فيه `status` صريح أو استخدمت `--status`.
  فإعادة التشغيل مش بترجّع المقالات المنشورة لـ draft.
- `--status` بيتطبّق على الموجود كمان — فاستخدمه وانت عارف.

### فشل مقال مش بيوقف الباقي

كل ملف لوحده. الخلاصة في الآخر بتقول نجح كام وفشل كام، والـ exit code بيبقى 1 لو فيه أي فشل.

### تصادم الـ slug = وقف، مش تنبيه

لو ملفين مختلفين بيوصلوا لنفس المقال، الأداة **بتوقف وبتفشل الملف** بدل ما تكتب فوق
مقال ملف تاني — لأن ده بيمسح محتوى منشور. بتقولك اسم الملف التاني، وانت تغيّر الـ slug
في واحد منهم. ولو لاقت مقال بنفس الـ slug مش مسجّل لأي ملف، بتنبّهك وبتكمّل.

### حاجات تحمي الموقع

| الحالة | السلوك |
|---|---|
| مقال فاضي (بدون نص) | **بيترفض** — النشر كان هيمسح محتوى المقال الموجود |
| تعديل الرابط الدائم من لوحة التحكم | **بيتحفظ** — الأداة بتبعت الـ slug بس لو انت غيّرته في الملف |
| تشغيلين في نفس الوقت | التاني بيترفض بقفل — كانوا بيعملوا نسخة مكررة من كل مقال |
| سجل نشر تالف أو لموقع تاني | بيتجاهل بهدوء، النشر بيكمّل بالـ slug |
| صورتين مختلفتين بنفس اسم الملف | صورتين منفصلتين (البصمة في الاسم) |
| `user:pass@` في `WP_SITE_URL` | **بيترفض** — كان بيظهر في كل رسالة خطأ |
| مقال في سلة المحذوفات | **بيترفض** — التحديث كان بيكتب جواه ومحدش يشوفه |
| مقال موجود بنفس الـ slug والأداة عمرها ما نشرته | تنبيه واضح قبل الكتابة فوقه |
| `status: future` بدون تاريخ | **بيترفض** — ووردبريس كان بينشره فورًا |
| الروابط الدائمة "Plain" | الأداة بتجرّب `?rest_route=` تلقائيًا |

### التوقيت والجدولة

ووردبريس بيفهم حقل `date` **بتوقيت الموقع**، والأداة ممكن تشتغل على سيرفر بتوقيت
تاني (الـ CI بيبقى UTC عادة). فالأداة بتقرا فرق توقيت الموقع من `/wp-json/` وبتبعت
`date_gmt` — يعني المقال ينزل في الوقت اللي انت كاتبه بتوقيت موقعك بالظبط.

لو الموقع مش بيعرض فرق التوقيت، حدّده بنفسك: `WP_SITE_GMT_OFFSET=3`.

ولو الموقع رجّع حالة مختلفة عن المطلوبة، الأداة بتنبّهك بدل ما تسكت.

### حاجات تانية

- **الصور مش بتترفع مرتين** — بتتعرّف بالرقم المسجّل وبالاسم.
- **الاختبار بالبايتات مش بالامتداد** — ملف نصي اسمه `.png` بيترفض، و SVG بترفض (ممكن تحتوي كود).
- **أسماء الصور العربية** بتتحول لـ ASCII (ترويسات HTTP مش بتشيل عربي)، والنص العربي بيتحفظ
  في `alt_text`.
- **فشل الـ SEO meta مش بيوقف النشر.** أغلب بلجنات السيو مش بتسجّل حقولها في REST، فالمقال
  ينزل عادي ويطلع تحذير. ده متوقع.

## الأمان

الأداة بتحمل باسورد لموقع حقيقي، فمطبّق فيها:

| الحماية | التفاصيل |
|---|---|
| الباسورد في `.env` بس | متجاهَل في git (في الجذر وفي المجلد) — متحطّهوش في أي ملف تاني |
| مش بيتبعت لمضيف تاني | الأداة بترفض أي redirect وبتثبّت المضيف على `WP_SITE_URL` |
| https إلزامي | موقع `http://` مرفوض إلا بـ `WP_ALLOW_HTTP=1` (تطوير محلي) |
| مفيش تسريب في المخرجات | `doctor` مبيطبعش أي حرف من الباسورد ولا حتى طوله |
| الصور محصورة | `featured_image` محلي لازم يبقى جوه مجلدات المشروع — مفيش `/etc/passwd` ولا `../..` |
| مفيش SSRF | الصور من URL: العناوين الداخلية والخاصة مرفوضة، مفيش اتباع redirect، حد أقصى للحجم |
| المحتوى بينزل خامل | كل نص مهرّب، وروابط `javascript:`/`data:` بتتشال، والـ HTML الخام بيتنقّى |
| الكتابة مش بتتكرّر | POST مبيتكرّرش أبدًا عند عطل مؤقت — إعادته كانت بتعمل مقالات مكررة |

**افعل ده:** اعمل يوزر مخصص للنشر بدور **Author** أو **Editor** — مش Administrator.
الـ Application Password بيشتغل بكل صلاحيات اليوزر بتاعه.

**لو الباسورد اتكشف:** امسحه من **Users → Profile → Application Passwords**. الإلغاء فوري
ومش بيأثر على دخولك العادي ولا على الباسوردات التانية.

## متغيرات البيئة

| المتغير | الوظيفة |
|---|---|
| `WP_SITE_URL` | عنوان الموقع (إلزامي) |
| `WP_USERNAME` | اليوزرنيم في ووردبريس (إلزامي) |
| `WP_APP_PASSWORD` | الـ Application Password (إلزامي) — المسافات بتتشال أوتوماتيك |
| `WP_CONTENT_DIR` | مكان المقالات (الافتراضي `./content`) |
| `WP_STATE_FILE` | سجل النشر (الافتراضي `./.published.json`) |
| `WP_ENV_FILE` | مكان ملف `.env` |
| `WP_ALLOW_HTTP=1` | السماح بموقع http — الباسورد هيتبعت مكشوف |
| `WP_ALLOW_LOCAL_FETCH=1` | السماح بتنزيل صور من عناوين محلية (للاختبار) |
| `WP_SITE_GMT_OFFSET` | فرق توقيت الموقع بالساعات — لو الموقع مش بيعرضه |
| `WP_MAX_RETRIES` | محاولات إعادة القراءة عند عطل مؤقت (الافتراضي 4) |
| `WP_TIMEOUT` | مهلة كل نداء بالثواني (الافتراضي 45) |

## الأتمتة

### GitHub Actions (جاهز)

`.github/workflows/publish-articles.yml` بيشتغل عند push على `content/`، أو بجدول يومي،
أو يدويًا. بيشغّل الاختبارات و `doctor` قبل النشر.

حُط الـ secrets في **Settings → Secrets and variables → Actions**:
`WP_SITE_URL` و `WP_USERNAME` و `WP_APP_PASSWORD`.

التشغيل المجدول **مش** بيبعت `--status`، فكل مقال بياخد الحالة المكتوبة في ملفه
والمقالات المنشورة تفضل منشورة.

### cron

```bash
0 9 * * * cd /path/to/wp-publisher && /usr/bin/python3 wp_publish.py publish --all >> publish.log 2>&1
```

### n8n

بدون كود: `Schedule` → `HTTP Request` على `https://موقعك/wp-json/wp/v2/posts` بـ Basic Auth
(اليوزر + الـ application password)، والـ body JSON فيه `title` و `content` و `status`.

## الاختبارات

فيه سيرفر ووردبريس مزيّف كامل، فالأداة بتتأكد من نفسها بدون ما تلمس موقع حقيقي:

```bash
python3 -m unittest discover -s tests        # 190 اختبار، حوالي 120 ثانية
python3 -m unittest discover -s tests -v     # بالتفاصيل
```

| الملف | بيغطي |
|---|---|
| `test_publish_core.py` | الإنشاء والتحديث ومنع التكرار، الحالة، المعاينة، اختيار الملفات |
| `test_security.py` | حصر مسارات الصور، SSRF، الـ redirect، https، حقن المحتوى |
| `test_failure_modes.py` | كل أعطال المصادقة والـ REST، البيانات الناقصة، الملفات البايظة |
| `test_media_terms.py` | الصور والتصنيفات والجدولة وحقول السيو والعربي |
| `test_markdown_blocks.py` | المحوّل: كل البلوكات، التهريب، المنقّي، المدخلات الشاذة |
| `test_state_and_identity.py` | أي ملف بيملك أي مقال، السجل، القفل، تصادم الـ slug، هوية الصور |
| `test_audit_gaps.py` | حمايات كان تعطيلها بيعدّي من السويت: الكتابة المتكرّرة، SSRF، حصر المسارات، التوقيت، صفحات التصنيفات، البديل بدون PyYAML |

وللتجربة اليدوية بدون موقع حقيقي:

```bash
python3 tests/mock_wp.py            # بيقوم سيرفر مزيّف ويطبع بياناته
python3 tests/mock_wp.py no_publish  # بسيناريو عطل معيّن
```

السيناريوهات: `ok`, `bad_auth`, `strip_auth`, `no_publish`, `no_upload`, `not_json`,
`flaky`, `flaky_write`, `rest_disabled`, `no_meta`, `silent_meta`, `missing_routes`,
`many_terms`.

المحاكاة مصمّمة تطابق ووردبريس الحقيقي في الحاجات اللي بتوقّع الأدوات: التحديث الجزئي
(الحقول اللي مش مبعوتة تفضل زي ما هي)، تشفير الـ slug غير اللاتيني بالنسبة المئوية،
استنتاج الحالة من `date_gmt`، وصفحة بعد النهاية بترجع 400 مش قائمة فاضية.

## استكشاف الأخطاء

**`401` مع إن البيانات صح** — أشهر سبب: السيرفر بيرمي ترويسة `Authorization` قبل ما توصل
لووردبريس (شائع على Apache + CGI/FastCGI). الحل في `.htaccess`:

```apache
SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1
```

**`403` على النشر** — دور اليوزر مالوش `publish_posts`. شغّل `doctor` وشوف الصلاحية الناقصة.

**الرد مش JSON** — REST API مقفول ببلجن أمان (Wordfence، iThemes، Disable REST API) أو بقاعدة
على السيرفر. اسمح لـ `/wp-json/wp/v2/*`.

**الأداة بترفض الموقع** — لو الموقع على `http` استخدم `https`، أو `WP_ALLOW_HTTP=1` لو ده
سيرفر محلي. ولو بتقول "redirect"، ظبّط `WP_SITE_URL` على العنوان النهائي (مع/بدون `www`).

**الصور مش بترفع** — `upload_files` ناقصة، أو بلجن بيحجب `Content-Disposition`، أو الصورة
أكبر من `upload_max_filesize`.

**تحذير SEO meta** — طبيعي، شوف فوق. المقال نزل.
